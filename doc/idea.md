# Заказы воды — план приложения (MVP)

## Цель

Android-приложение с двумя виджетами для сотрудника, принимающего заказы воды по телефону.
Главная боль: после звонка забывают записать адрес и количество бутылок.

MVP: локальный учёт входящих звонков + напоминание о необработанных.
Google Таблица намеренно отложена на будущее (см. раздел «Отложено»).

## Пользователь и окружение

- Один оператор, одно устройство. Без аккаунтов и синхронизации.
- Современные телефоны: `minSdk 30` (Android 11), `targetSdk 35`.
- Название приложения: «Заказы воды». Язык интерфейса — русский.

## Сценарий работы

1. Поступает входящий звонок. Оператор отвечает и разговаривает.
2. После завершения звонка приложение создаёт запись «необработанный звонок»
   (если номер не в белом/чёрном списке — см. «Не клиент»).
3. Первый виджет показывает последний звонивший номер. Тап по нему открывает
   мини-форму: количество бутылок, адрес, пометка «не клиент».
4. Второй виджет показывает счётчик необработанных звонков и меняет цвет.
   Тап по нему открывает экран-список необработанных.
5. На экране-списке одна кнопка «Заказы обработаны» закрывает все записи списка.
   Доверяем оператору.
6. Кнопка «Проверить таблицу» сверяет необработанные записи с Google Таблицей
   (см. «Проверка по Google Таблице»).

## Правила обработки звонков

- Источник событий: `PHONE_STATE` (BroadcastReceiver) + «добор» из `CallLog`,
  если номер в `PHONE_STATE` пришёл пустым (задержка 3–5 сек после окончания звонка).
  Отвечен ли звонок, определяется по переходу в `OFFHOOK`, а не по журналу.
  Если журнал отстал сильнее, номер дозаполняется позже, при открытии списка.
- Запись создаётся сразу после завершения звонка, не дожидаясь журнала:
  оператор открывает форму через секунду-две и должен видеть номер.
  Если номер в `PHONE_STATE` пустой, журнал опрашивается один раз;
  `callLogId` и номер дозаполняются позже, при следующей сверке.
- Пока приложение не запущено, система не доставляет `PHONE_STATE`
  (сразу после установки пакет остановлен). Поэтому при старте приложения
  звонки за последние 6 часов восстанавливаются из журнала.
- Учитываются только входящие звонки; исходящие игнорируются.
- Запись создаётся после завершения звонка (переход в `IDLE`), а не во время.
- Важен только сам факт звонка и кто звонил; длительность не сохраняется
  и нигде не используется.
- Отвеченный звонок (был `OFFHOOK`) учитывается всегда, включая нерабочее
  время. Пропущенный/сброшенный звонок учитывается только в рабочее время.
- Рабочее время — настройка: время «с–до» и чекбоксы рабочих дней недели
  (одно окно для всех отмеченных дней). Вне окна пропущенные звонки не
  создают записей вообще.
- Отвеченный звонок вне рабочего времени тоже попадает в необработанные:
  оператор уже поговорил с клиентом, и заказ нельзя терять из счётчика.
- Скрытый/неизвестный номер — создаём запись с пометкой «скрытый номер»;
  такие записи не склеиваются между собой.
- Поддерживаются все активные SIM.
- Номер нормализуется для РФ/СНГ: `+7`, `8`, `7` и `9XX…` приводятся к одному виду.
- Имя звонящего подтягивается из контактов (`READ_CONTACTS`), если найдено;
  иначе показывается только номер.
- Каждый сохранённый звонок хранит `callLogId`. Перед показом списка и
  обновлением виджета необработанные записи сверяются с системным журналом:
  если звонка в журнале больше нет (оператор удалил его из истории), запись
  автоматически закрывается как «удалена из истории» и убирается из списка.
  Обработанные записи и сохранённые заказы журнал не затрагивает.
- Звонок с контакта на другой адрес — это обычный заказ, адрес вводится в
  поле формы. Никаких отдельных сущностей для адресов в MVP нет.
- Контакт и есть адрес доставки. Если оператор не ввёл в поле адреса ничего
  своего, адресом считается имя контакта: поле в форме подставляется именем
  контакта, а сверка с таблицей идёт по нему.

## Неизвестный номер → контакт

- Если номер не найден в телефонной книге, в мини-форме появляется поле «Имя»
  (только для неизвестных номеров; для скрытого номера поля нет).
- При сохранении формы с заполненным именем приложение само создаёт контакт
  в телефонной книге.
- На этапе онбординга оператор выбирает Google-аккаунт; контакт пишется в
  выбранный аккаунт. Если Google-аккаунта нет — откат на локальную книгу
  устройства с пояснением в интерфейсе.
- Дубликатов не создаём: перед записью номер ищется в книге (нормализованно),
  и если контакт уже есть, новый не создаётся.
- Имя обязательно для контакта: если оператор ввёл только адрес без имени,
  заказ сохраняется, но контакт не создаётся.
- Если оператор сам сохранил контакт в телефонной книге, имя подхватывается
  из книги при открытии экрана-списка (таблицы). Запись при этом остаётся
  необработанной — закрывает её только кнопка «Заказы обработаны».
  Оператор обычно делает это в первые 5–10 минут.

## Проверка по Google Таблице

Оператор заносит выполненные заказы в Google Таблицу; приложение умеет
сверять с ней необработанные звонки.

- Запуск — вручную кнопкой «Проверить таблицу» на экране-списке.
- Таблица доступна по ссылке без авторизации, приложение только читает её:
  `docs.google.com/spreadsheets/d/1HDK5_dbN52XIE3XScBhVJtvtJvgbEMwH8U6Trozjmqg`.
- Скачиваются CSV-вкладки за сегодня и завтра. Имя вкладки — дата в формате
  `дд.ММ.гг` (например `27.10.26`). Служебные вкладки (`Клиенты`, `*_tg_queue`,
  `*_tg_state`) не читаются. Если вкладки за какой-то из этих дней ещё нет,
  она просто пропускается.
- Заказы в таблице лежат тремя блоками: адрес в колонках `B`, `I`, `Q`,
  количество бутылей — в соседней справа ячейке (`C`, `J`, `R`).
  В одной строке листа может быть до трёх заказов; они считаются
  независимыми: закрытие одного не мешает другим.
- Адреса сравниваются нормализованно (регистр, `ё`, пунктуация, пробелы,
  дефисы не важны). Точное совпадение закрывает запись как обработанную
  (`closeReason = SHEET`).
- Количество бутылей — подсказка: расхождение с таблицей не мешает закрытию,
  но попадает в итог проверки.
- Одна строка таблицы закрывает не более одной записи — самой свежей.
  Израсходованная строка запоминается, поэтому повторная проверка не закроет
  по ней ещё одну запись. Ключ — вкладка, номер строки и колонка адреса,
  потому что в строке до трёх заказов.
- Сначала точные совпадения ищутся для всех записей и только потом
  предлагаются похожие адреса. Поэтому похожий адрес одной записи не
  занимает строку, по которой у другой записи есть точное совпадение.
- Неполное совпадение (похожий адрес) ничего не закрывает само: оператор
  подтверждает, что это тот же адрес, и пара сохраняется как синоним.
  В следующий раз такой адрес считается точным совпадением.
  Оператор может и отказаться: «Не тот же адрес» — тогда пара больше
  не предлагается.
- Похожим считается адрес, слова которого идут подряд внутри другого:
  «Город женский» и «Континент город женский» — кандидат. Адрес из одного
  слова кандидатом не считается, чтобы не сравнивать всё со всем.
- Синонимы хранятся локально, в таблицу ничего не пишется.
- Без сети или при ошибке загрузки показывается сообщение, данные не меняются.
- Скачанные вкладки живут только в памяти и только пока открыт результат
  проверки: на диск ничего не сохраняется, после закрытия диалога данные
  освобождаются.

## Не клиент

- Пометка ставится из мини-формы первого виджета.
- Два режима:
  - **постоянно** — номер больше не создаёт записей;
  - **временно** — действует только до следующего звонка, затем снимается
    автоматически (например, клиент звонил просто уточнить).
- Пометку можно снять вручную в форме.

## Модель данных (Room, локально)

`CallRecord` (запись = звонок):

- `id`, `phoneNormalized` (nullable — скрытый номер), `displayName` (nullable)
- `callLogId` (nullable — для сверки с системным журналом)
- `incomingAt`
- `bottlesText` (свободный текст), `addressText` (свободный текст).
  Адрес доставки — `addressText`, а если он пуст, то `displayName` (контакт).
- `isProcessed` (закрыт кнопкой «Заказы обработаны»), `processedAt`
- `isSkipped` (номер был помечен «не клиент»)
- `isSilent` (звонок вне рабочего времени — не сигналит и не считается)
- `deliveryDay` (`TOMORROW` | `DAY_AFTER_TOMORROW` | `MONDAY` | `OTHER_DAY`,
  `null` — день не отмечен); в старых базах рядом остаётся `isNextDay`
- `closeReason` (`DONE` | `DELETED_FROM_CALLLOG` | `SHEET`)

`WorkSchedule` (DataStore/настройки):

- `startTime` (по умолчанию 08:00), `endTime` (по умолчанию 17:00)
- `workDays` — набор дней недели (по умолчанию пн–пт)

`BlacklistEntry`:

- `phoneNormalized`, `kind` (`PERMANENT` | `ONCE`), `createdAt`

`AddressAlias` (решения по адресам, локально):

- `aliasNormalized` — как адрес записан в приложении (нормализованно);
- `canonicalNormalized` — как тот же адрес записан в таблице;
- `kind` (`MATCH` — это один адрес, `REJECT` — разные адреса);
- `createdAt`.

`CallRecord.sheetMatchKey` — ключ строки таблицы (`вкладка:номер строки`),
если запись закрыта проверкой таблицы. Нужен, чтобы одна строка таблицы
не закрывала повторно ещё одну запись.

`CustomerSummary` не хранится отдельно — «сколько заказывали раньше» берётся
из последней записи этого номера с непустым заказом.

Поведение при повторах:

- Пока запись не обработана, повторный звонок того же номера обновляет эту же
  строку (время звонка новое, введённые данные сохраняются).
- После «обработано» следующий звонок создаёт новую строку, а прошлые заказы
  видны в колонке «раньше».
- Клиент может заказывать на два разных адреса. В форме есть кнопка
  «Ещё адрес»: текущий заказ сохраняется, а в списке появляется вторая
  карточка с тем же номером и пустыми полями. Строка таблицы закрывает
  не более одной карточки, поэтому второй заказ не потеряется.

## Экраны и виджеты

Приложение:

1. Онбординг — запрос разрешений и исключения из оптимизации батареи.
2. Экран-список необработанных — контакт, телефон, бутыли, «раньше», время
   звонка, кнопки «Заказы обработаны» (закрывает всё сразу) и «Проверить
   таблицу». Только необработанные, история остаётся в базе.
3. Экран настроек (шестерёнка на экране-списке) — рабочее время: «с–до»
   и чекбоксы рабочих дней.

Виджеты:

1. **Записать заказ** — квадрат 1x1, на нём только иконка (трубка; число
   звонящих не показываем). Тап открывает форму с последним звонком: имя и
   номер, бутыли, адрес, переключатель дня доставки (пн–чт «завтра /
   послезавтра / другой день», пт «завтра / понедельник / другой день»,
   сб–вс «понедельник / другой день»; без выбора по умолчанию), поле «Имя»
   (только для неизвестного номера), пометка «не клиент», кнопки
   «Предыдущий звонок» и «Сохранить и закрыть».
   Поле адреса подставляется именем контакта, если оператор не ввёл своё.
   Кнопка закрытия формы не отмечает звонок обработанным — обработанным
   делает только кнопка на экране-списке. «Предыдущий звонок» листает назад
   по необработанным записям в пределах сегодняшнего дня.
2. **Незаписанные** — 2x2, крупный счётчик необработанных звонков + цветовая
   индикация (спокойный вид при нуле). Тап открывает экран-список.

Обновление виджетов — push из ресивера после каждого звонка, а также после
сохранения формы и нажатия «Заказы обработаны».

## Разрешения и системные ограничения

- `READ_PHONE_STATE` — определение звонков.
- `READ_CALL_LOG` — добор номера и сверка удалённых звонков.
- `READ_CONTACTS` — имя звонящего.
- `WRITE_CONTACTS` и `GET_ACCOUNTS` — создание контакта для неизвестного номера
  в выбранном Google-аккаунте.
- `INTERNET` — чтение Google Таблицы по кнопке «Проверить таблицу».
- Исключение из оптимизации батареи запрашиваем в онбординге, объясняя,
  что иначе звонки и обновления виджета могут пропускаться.
- Включён Android auto-backup (данные переживут переустановку).

## Технологии

- Kotlin, Jetpack Compose для экранов, Room для данных.
- Виджеты — классические `RemoteViews` (`AppWidgetProvider`) для предсказуемого
  поведения; экраны из виджетов открываются как Activity.
- Единственный сетевой запрос — чтение Google Таблицы по нажатию кнопки;
  всё остальное работает офлайн.

## Работы по этапам

1. Каркас проекта, Room-схема, онбординг с разрешениями и выбором
   Google-аккаунта для контактов.
2. Перехват звонков (`PHONE_STATE` + `CallLog`), сохранение `callLogId`,
   нормализация номера, определение имени, создание/обновление `CallRecord`.
3. Мини-форма последнего звонка, логика «не клиент» и создание контакта
   для неизвестного номера.
4. Экран-список необработанных, кнопка «Заказы обработаны», сверка с
   журналом для закрытия удалённых звонков, экран настроек рабочего времени.
5. Два виджета и push-обновление.
6. Тесты: нормализация номеров, правила создания/склейки записей, пометки
   «не клиент», обработка пустого номера, сверка с журналом, отказ от
   создания дубликата контакта, разбор CSV таблицы и сопоставление адресов.

## Отложено (не в этом MVP)

- Запись в Google Таблицу и любая двусторонняя синхронизация (приложение
  только читает таблицу).
- Полная история заказов с поиском.
- Всплывающие уведомления после звонка.
- Экспорт данных вручную.
- Разные окна рабочего времени по дням недели (в MVP одно окно на все
  отмеченные дни).
- Настройка выбора SIM.
- Справочник адресов клиента и явная метка «другой адрес»: в MVP адрес —
  просто текстовое поле, связка клиент↔адрес не ведётся.

## Открытые вопросы

- Формат записи в Google Таблицу, когда до неё дойдём (столбцы, кто пишет,
  что делать при отсутствии сети).
