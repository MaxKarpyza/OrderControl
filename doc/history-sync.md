# Общая история операторов (вкладка `history`)

Раньше история обработанных заказов была только на телефоне: каждый оператор
видел лишь свои записи. Теперь обработанные заказы складываются в отдельную
вкладку таблицы `history`, и любой оператор видит чужие — в первую очередь
ради **телефона, с которого приняли заказ**: по нему можно связаться с
клиентом, если водитель просит.

Вкладка служебная: после отладки её можно скрыть (правая кнопка по вкладке →
**Скрыть лист**). Приложение читает её через скрипт, а не через публичную
ссылку, поэтому скрытость значения не имеет.

## Что в строке

| Колонка | Содержимое |
|---|---|
| `id` | `опер_NN-КОД:номер записи:время` — по нему строка отличается от других и не дублируется при повторной отправке |
| `автор` | ФИО из настроек или `опер_NN-КОД` |
| `телефон` | номер, с которого приняли заказ; **без телефона строки нет** |
| `адрес` | адрес доставки |
| `район` | район из записи или из базы адресов |
| `бутыли` | количество |
| `комментарий` | текст оператора |
| `обработано` | время обработки (ISO) |
| `создано` | когда строка появилась; по нему идёт очистка |

Дальше, начиная с колонки `K`, — служебный список операторов: кто, когда
впервые и в последний раз забирал историю. Он нужен, чтобы видеть, кто из
телефонов реально пользуется общей историей.

## Сколько хранится

Строка живёт **2 суток** с момента создания. При каждом обмене скрипт удаляет
всё, что старше, — таблица не разрастается. Записи старше двух суток
приложение в таблицу и не отправляет.

Один адрес может встретиться несколько раз: это история, а не справочник.
Если два оператора приняли заказ на один адрес с разных номеров, в истории
будут обе строки — и оба телефона.

## Кто есть кто

При первом обмене приложение генерирует постоянное имя телефона —
`опер_37-A3F`: номер случайный двузначный, код — три символа из идентификатора
устройства, поэтому два телефона не могут получить одинаковое имя.

В настройках есть поле **Имя, отчество** — если заполнить, в колонке `автор`
будет ФИО. `id` строки при этом не меняется: по нему приложение понимает, что
эта строка своя, и не показывает её в общей истории.

## Когда происходит обмен

- при отправке заказов в таблицу (кнопка «В таблицу») — заодно с записью;
- сразу после того, как оператор отметил запись обработанной;
- после сверки с таблицей, если сверка что-то закрыла;
- вручную — кнопка обновления на вкладке «История».

Обмен — один `POST` к тому же Apps Script (`action: "sync"`). Он отправляет
новые свои записи, забирает чужие и просит скрипт почистить старое.

## Как это выглядит в приложении

На вкладке «История» появился переключатель **Мои / Все**:

- **Мои** (по умолчанию) — только свои записи, как раньше;
- **Все** — плюс записи других операторов, с подписью автора.

Чужие записи только читаются: их нельзя «вернуть в необработанные» или
изменить — они принадлежат другому телефону. Позвонить по номеру можно, как и
по своим.

Если своих записей нет, а у других уже есть, вкладка предлагает показать всех.

## Если скрипт не обновлён

Приложение определяет это по ответу скрипта (`no_tab` вместо истории) и
показывает сообщение «Общая история не работает: скрипт в таблице не
обновлён». Запись заказов при этом продолжает работать.

Обновление — **Развернуть → Управление развёртываниями → карандаш → Версия:
Новая версия → Развернуть** (URL не меняется). Код — в
[table-write.md](table-write.md); после выкладки `GET` по URL веб-приложения
должен вернуть `"version":3` и `"historyTab":true`.

## Проверка после обновления

1. `GET` по URL веб-приложения возвращает `"version":3`.
2. Отметить одну запись обработанной на телефоне A.
3. На телефоне B открыть «История» → **Все**: строка должна появиться с
   подписью A и его ФИО (или `опер_NN-КОД`).
4. Нажать обновление на телефоне B: в таблице появилась вкладка `history` со
   строкой; в колонке `K` — список операторов.
5. Проверить, что через двое суток строки исчезают (или видно, что скрипт их
   удаляет при следующем обмене).
